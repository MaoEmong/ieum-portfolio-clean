# AI 협업으로 진행한 백엔드 개발

개발·배포 환경의 설정 검사, 파일 API의 오류 분류, 회귀 테스트에 AI 코딩 도구를 활용했습니다. 프로젝트 주도자(지원자, 이하 주도자)는 요구사항과 작업 범위를 정하고 변경을 승인했으며, AI는 분석·구현·시험을 지원했습니다.

아래 내용은 실제 개발 대화와 사후 검증 기록을 포트폴리오용으로 편집한 설명입니다. 직접 인용이나 당시 AI 답변의 재현이 아닙니다.

## 1. 개발·배포 분리를 서버의 실행 조건으로 구체화

주도자는 개발 환경에서 SNS 로그인 없이 작업하고, 배포 환경에서는 실제 인증과 테스트를 거쳐 배포하는 작업 흐름을 요구했습니다. 이후 저장소 연결 점검에서는 배포 환경의 저장 모드 설정이 누락된 상태를 공유했습니다.

AI 지원 작업은 이 환경 정보를 바탕으로 잘못된 설정을 재현하는 검사부터 시작했습니다. 알 수 없는 저장 모드, production에서의 로컬 저장, 불완전한 객체 저장소 설정을 검사하고, 해당 조합을 서버 기동 단계에서 거부하도록 설정 검증 코드를 보완했습니다.

2026-09-08 사후 기록에는 최초 설정 테스트 8개 중 7개 실패, 구현과 검사 항목 보완 후 설정 테스트 10개 통과가 남아 있습니다. SDK 요청 계약 검사 4개와 실제 저장소 연결 확인도 구분해 진행했습니다.

```text
작업 흐름 정의 → 배포 설정 확인 → 잘못된 설정의 실패 재현
             → 기동 조건 보완 → 설정·SDK 검사 → 실제 연결 확인
```

설정의 안전한 조합을 기동 조건으로 강제하고, 단위 검사와 외부 저장소 연결 검사를 나누어 확인한 사례입니다.

## 2. 파일 부재를 재현하고 API 오류 계약을 수정

기존 파일을 찾을 수 없다는 조사 결과가 보고된 뒤, 주도자는 수정 진행을 승인했습니다. 기존 기록·전사문·파일 참조를 보존하는 범위에서 오류 처리와 저장소 연결을 보완했습니다.

AI는 로그와 저장 경로 대조, 명시적인 파일 부재와 일반 장애의 분류, 구현 및 회귀 검사를 지원했습니다. 수정된 파일 API는 명시적인 파일 부재에 404를 반환하며, 권한·일반 I/O·설정 오류를 같은 상태로 바꾸지 않습니다. 기존 인증·소유권 검사 순서도 유지했습니다.

| 개발 단계 | 2026-09-08 기록에서 확인한 결과 |
|---|---|
| 실패 재현 | 신규 백엔드 회귀 22개 중 6개에서 기대 404 대신 500 반환 |
| 수정 후 검사 | 신규 회귀와 기존 저장소 검사 28개 통과 |
| 전체 회귀 | 백엔드 210개 통과. 보관된 테스트 XML 집계와 대조 |
| 배포 후 확인 | 신규 합성 사진 1개를 재배포 뒤 새 앱 프로세스에서 조회하고 저장 바이트 대조 |

부분 검사 수는 전체 검사 수에 포함되므로 합산하지 않습니다. 신규 사진의 보존과 파일 부재 응답을 확인했으며, 기존 누락 원본은 복구하지 못했습니다.

## 3. 변경 승인 뒤 실제 이용 순서로 재검증

주도자는 AI가 제안한 입력 본문 보존 방식을 승인하고, 앱 이용 시나리오에 따른 점검을 요청했습니다. AI 지원 검증에서는 검수·전체 모아보기의 본문 보존, 약속 후보의 기본 미선택과 명시적 확정, 편집 후 뒤로가기 경로를 다뤘습니다.

2026-09-08 사후 기록은 자동 회귀, 실기기 재시험, 이후 로컬 보완을 서로 다른 검증 시점으로 구분합니다. 빌드 성공을 전체 실기기 검증으로, 테스트 개수를 커버리지로, 사진 한 개의 보존 확인을 전체 원본 복구로 확대하지 않았습니다.

이 협업에서는 요구사항을 구현 조건으로 바꾸고, 실패를 재현한 뒤 수정 결과를 비교하며, 실제로 확인한 범위까지 결과를 보고했습니다. [의사결정·검증 요약](evidence/ai-collaboration-summary.md)과 [서비스 검증 범위](verification.md)에서 역할과 근거 유형을 확인할 수 있습니다.
