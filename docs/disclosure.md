# 공개 범위와 소유자 검토

현재 상태: **PRIVATE / 소유자 검토 대기**. 공개 전환은 자동화하지 않습니다.

## 포함한 것

| 분류 | 처리 |
|---|---|
| 서비스 소개·사용자 흐름 | 공개 설명용으로 새로 작성 |
| 논리 아키텍처·기술 선택 | 운영 주소·스키마·비밀값 없이 재작성 |
| 기술 사례·검증 수치 | 내부 근거에서 사실과 한계만 추려 재작성 |
| 화면 | 실제 Flutter 화면을 합성 데이터로 렌더링 |
| 대표 코드 | Spring 오류·기동 경계와 Dart 재시도·시간 보존을 독립 예제로 재구성 |
| AI 협업 근거 | 개발 대화를 다듬은 의사결정 요약과 사후 검증 기록. 직접 인용·대화 재현·제품 런타임 프롬프트는 제외 |
| PDF | 이 저장소의 선별 내용으로 새로 작성 |

## 가져오지 않은 것

- 서비스 레포와 이전 포트폴리오의 `.git` 이력·브랜치·태그·PR·이슈·작업 로그
- 제품 런타임 AI 프롬프트, 추출·검색·랭킹의 상세 구현, 모델 설정·평가 코퍼스
- 서버·DB·Storage의 실제 접속 주소와 식별자, 인증·배포 설정
- 키, 토큰, 비밀번호, 앱 서명 파일, 환경변수 파일
- 실제 인물·음성·명함·메모, DB 내보내기, 원본 파일·백업
- APK/AAB, 네이티브 라이브러리·모델 파일, 내부 사업계획서

검토된 현재 파일만 복사하고 Git 이력을 새로 시작했습니다. 기존 저장소의 fork·템플릿·이력 가져오기를 사용하지 않았으며, 서비스 레포의 자동 미러나 동기화 설정도 없습니다. 파일은 `disclosure-allowlist.txt`에 적힌 경로만 추적하도록 검사합니다.

**공개 전 확인:** 새 저장소의 전체 이력과 GitHub에서 받은 새 복제본을 검사하고, 제거 대상 원문을 담았던 이전 커밋 및 당시 문서·PDF·생성 코드의 특정 파일 객체가 이 저장소에서 조회되지 않는지도 별도로 확인합니다. 허용한 동일 파일은 내용 기반 Git 식별자가 같을 수 있습니다. 이는 기존 비공개 저장소나 그 복제본을 삭제했다는 뜻이 아닙니다. 공개 여부는 이 저장소의 문서·PDF·예제·이력을 검토한 뒤 소유자가 결정합니다.

## 자동 검사와 사람의 검토를 분리

`scripts/check_disclosure.py`는 명시적 파일 목록과 금지 패턴을 검사합니다. `--history`는 로컬 참조에서 도달 가능한 커밋의 파일 내용을 검사하며, 무시된 작업 파일·reflog·도달 불가능한 객체·커밋 메시지와 작성자 정보는 검사하지 않습니다. 새 저장소의 실제 커밋 메시지와 작성자 정보는 별도로 확인합니다. 합성 화면의 시각 내용, 설명이 핵심 노하우를 과도하게 드러내는지, 권리·브랜드 사용 범위는 자동 정규식만으로 판단할 수 없습니다.

기밀 구현을 앱 바이너리로 배포하면 소스가 비공개여도 일부를 분석할 수 있습니다. 그래서 이 포트폴리오에는 서비스 APK나 모델 산출물을 첨부하지 않습니다. 소스 비공개는 서버 보안 대책이 아닙니다.

## 소유자가 public 전환 전에 확인할 것

- [ ] README·PDF의 소개, 역할과 검증 수치가 본인의 설명 의도와 일치한다.
- [ ] 기술 사례와 예제의 공개 수준이 사업적으로 괜찮다.
- [ ] AI 협업 요약·역할 구분이 본인의 경험과 일치하며 공개해도 괜찮다.
- [ ] 독립된 Git 이력과 새 복제본에 원문 발언·과거 PDF·내부 자료가 없는지 검사했다.
- [ ] 제거 대상 원문을 담았던 이전 커밋과 해당 문서·PDF·생성 코드의 특정 파일 객체가 새 저장소에서 조회되지 않는지 확인했다.
- [ ] 화면 속 인물·메모·일정이 모두 합성 자료이며 개인정보가 없다.
- [ ] 저작권·재사용 범위와 제3자 표시를 확인했다.
- [ ] 파일 목록과 전체 Git 이력에 공개하면 안 되는 파일이 없다.
- [ ] 공개 뒤 다른 사람이 만든 복사본을 완전히 회수할 수 없다는 점을 이해한다.
- [ ] PDF의 저장소 링크는 private 동안 채용 담당자가 열 수 없음을 확인했다.

승인 후에도 소유자가 GitHub에서 가시성을 변경하기 전까지는 private를 유지합니다. 변경 시 README와 이 문서의 검토 상태도 함께 갱신합니다.
