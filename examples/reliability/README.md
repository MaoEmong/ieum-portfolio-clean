# 신뢰성을 설명하는 작은 Dart 예제

비공개 앱에서 다룬 두 문제를 설명하기 위해 **새로 작성한 독립 예제**입니다. 원본 코드 발췌나 제품의 축소판이 아닙니다. 실제 서비스, 계정, 데이터 없이 실행됩니다. Dart SDK 3.10 이상 4.0 미만이 필요하며 Flutter는 필요하지 않습니다.

```sh
dart pub get
dart analyze
dart test
dart run example/main.dart
```

각 예제만 실행하려면 다음 명령을 사용합니다.

```sh
dart run example/retry.dart
dart run example/event_time.dart
```

`pubspec.lock`을 함께 보관해 검증한 테스트 의존성을 재현합니다. 실행 코드에는 외부 패키지 의존성이 없고, 테스트에만 `package:test`를 사용합니다.

## 1. 재시도할 실패를 구분하고 기다림의 끝을 정하기

`BoundedRetry`는 다시 시도할 여지가 있는 읽기 실패만 정해진 횟수 안에서 반복합니다. 일시적 연결 실패·서비스 불가·요청 제한·인증 준비 중은 재시도하고, 잘못된 요청·접근 거부·없는 리소스는 즉시 종료합니다. 기본 일정은 250ms, 750ms로 최초 시도를 포함해 최대 세 번 호출합니다. 일정만의 총 대기는 1초입니다.

CLI는 가짜 읽기 작업과 주입한 대기 함수를 사용해 재시도 순서를 출력합니다. 실제 네트워크 요청이나 대기를 수행하지 않습니다. 테스트에서는 성공, 최종 실패, 중간에 영구 실패로 바뀌는 경우, 음수 횟수, 빈 일정, 대기 함수의 실패를 확인합니다.

원래 사례의 핵심은 실패 분류와 재시도 상한을 통해 무의미한 로딩을 줄이는 것이었습니다. 이 예제에서는 프레임워크 연결을 제거하고 오류를 독립 열거형으로 바꿨습니다. 재시도 간격도 설명용으로 새로 정했습니다. 원래 사례와 달리 알 수 없는 예외는 즉시 종료합니다. HTTP 응답이나 인증 상태를 열거형으로 분류하는 작업은 호출자의 책임입니다.

이 코드는 읽기 또는 멱등성이 확보된 작업을 전제로 하며, 멱등성이나 중복 실행 방지를 보장하지 않습니다. 일정의 상한은 전체 실행 시간의 상한이 아닙니다. 작업 한 번의 타임아웃, 취소, `Retry-After`, 지터, 여러 호출 계층 사이의 재시도 조정은 구현하지 않았습니다.

## 2. UTC 시각과 지역 식별자를 함께 저장하기

`EventStamp`는 절대 시각을 UTC로, 당시의 지역 문맥을 `zoneId`로 따로 저장합니다. JSON을 다시 읽을 때 장치의 현재 시간대를 참조하지 않으므로 이동이나 재시작 뒤에도 두 값이 유지됩니다. CLI의 합성 데이터는 같은 `01:30`과 같은 지역 이름도 명시적 오프셋이 다르면 서로 다른 순간임을 보여 줍니다.

저장 형태는 다음과 같습니다.

```json
{
  "version": 1,
  "instantUtc": "2030-06-15T06:00:00.000Z",
  "zoneId": "Asia/Tokyo"
}
```

원래 사례에는 기록의 시각·지역을 저장하고 복원하는 경로와 예전의 지역 시각 데이터를 해석하는 처리가 있었습니다. 이 예제는 그중 **UTC + 지역 식별자의 왕복 보존**만 재구성했습니다. 앱의 저장소, 업로드 큐, API, 과거 데이터 마이그레이션은 포함하지 않습니다. 버전 필드와 엄격한 UTC JSON 검증은 설명을 위해 추가한 규칙이며 제품의 스키마가 아닙니다.

생성자는 UTC `DateTime`을 요구하고, 복원은 이 예제가 만든 정규 UTC 문자열만 받아들입니다. 지역 시각 또는 오프셋 없는 문자열을 조용히 추측하지 않습니다. 날짜 자동 보정으로 잘못된 입력이 다른 날짜가 되는 것도 문자열 왕복 검증으로 거부합니다. 테스트는 윤일, 마이크로초, 명시적 오프셋이 다른 두 순간, 잘못된 날짜, 누락 필드, 버전 오류를 다룹니다.

지역 식별자는 문법만 검사합니다. IANA 데이터베이스 조회, 지역별 실제 오프셋 검증, 화면용 지역 시각 변환, 일광절약시간의 빈 구간·중복 구간 해결, 반복 일정은 이 예제의 범위 밖입니다. 호출자가 UTC 시각을 확정하고 적절한 지역 이름을 함께 제공해야 합니다.

## 공개 범위

예제는 일반적인 설계 판단을 검토할 수 있도록 만든 포트폴리오 자료입니다. 합성 입력만 사용하며 제품의 핵심 구현, AI 프롬프트, 검색 내부 동작, 서비스 주소, 실제 식별자와 비밀 값은 포함하지 않습니다. 테스트 통과는 이 독립 예제의 동작을 보여 주며 원래 앱 전체의 품질이나 성능을 증명하지 않습니다.
