# Portfolio boundary

- This is a curated portfolio, not the production service.
- The owner approved public release on 2026-09-08. Only this curated portfolio is public; the service repository and previous portfolio remain private.
- This is an independent repository with a new root commit. Never import the service repository, a previous portfolio's Git history, or their branches, tags and remotes here.
- Do not introduce real service endpoints, secrets, user data, runtime AI prompts, proprietary search/processing code, APKs, model files or raw internal reports.
- Use edited summaries of development decisions, not verbatim conversation excerpts. Label summaries as edited descriptions; never invent historical prompts, timestamps or human authorship. Check both reachable history and hosted references before public release; a clean working tree alone is not sufficient.
- Distinguish historical service evidence, newly reconstructed examples, and current verification. AI-generated code and test output do not by themselves prove human authorship or productivity gains.
- All screenshots use fabricated data; disclose whether they are widget renders or device captures.
- Keep verification claims scoped and dated. Never convert test counts into coverage or user capacity.
- Use only files listed in `disclosure-allowlist.txt`. Run the disclosure checker, its tests and the Dart example checks before pushing.
- No live-service credentials, service deployment workflows, additional public hosting or automatic visibility changes. Changing another repository's visibility requires separate owner approval.
- Do not grant a new open-source license without the owner's decision.
